# C5VRX-4 bug audit — 2026-10-03

C5VRX by Twotoz (Leon Beekveldt) and contributors. Review base: main `e15c6ee` (PR159). This extends its isolated Unwrap75 / Direct Gain V5 integration. The source is MODEM_DIAG Q4/I4 at 40 MS/s, a raw cyclic ring, TX-only BitScrambler with three bundles, unique 13.333 MS/s and [D,D,D] at physical DAC40M. These fixes are control/snapshot changes; no DSP or per-sample CPU route is introduced.

## Confirmed defects repaired here

1. **Sparse gain and sentinel snapshots can accept overwritten data.** The old probe accepted a 300-us copy when the 16-KiB ring could return to the sampled full node after only 205 us (two 4092-byte nodes and the 16-byte tail). A pointer comparison alone misses a lap. The sentinel lacked an elapsed deadline. Both now reuse the completed-copy guard, based on actual node lengths and forward progress. Fusion, RSSI lab and scan rank copies also stop using an unchecked pointer/fallback into the active raw ring. This prevents stale control evidence, not a claimed RF-stream repair.
2. **Scanner endpoint copies lacked any overwrite or context check.** The 8184-byte circular copy now rejects elapsed time beyond the remaining safe bytes, changed profile/PHY/gain/lane and active PHY transactions. With a full active node in a 16-KiB ring its conservative horizon is 102 us. Slow copies lower availability rather than manufacture a valid channel. PAL/NTSC and Wi-Fi scanner A/B remains required.
3. **Gain decisions lacked a second context check after processing/acquiring the actuator.** Ordinary V5 observations now recheck gain/profile/PHY/table generations before ticking. The actuator rechecks profile/mode/menu/scan after ownership acquisition. Scan also refuses conflicting USB commands; T diagnostics remain available. Menu already excluded ordinary gain observation, but USB lives in another task.
4. **Level-lab updates were stopped after TX had already been disabled.** Menu entry and self-noise teardown now drain/refuse level writes before disabling PARLIO/BitScrambler. The existing recursive LUT mutex serializes the stop against a current update. No new running LUT-write policy is enabled.

The concurrent open [PR161](https://github.com/Twotoz/C5VRX/pull/161) independently covers stale CVBS level-evidence chains and voltage-ordered DAC slew. Its code is not duplicated in this PR.

The suspected fixed-ultrafine last-resort downshift was disproved: the existing central `set_lane()` already refuses all lane changes in fixed mode. A regression against the unchanged controller confirmed this; no redundant fix is included.

## Remaining evidence gaps / possible bugs

- Fine/ultrafine noncontiguous ADC lanes can fold. A protected overlap window does not establish independent full-ADC headroom; GPIO route writes are sequential and untagged. Abrupt strong-carrier and cross-lane physical tests remain necessary (#125 lineage).
- Live LUT16 arbitration, FIFO continuity and intermediate regulated transfers remain unproven. The u level lab remains off by default. Readback is not a transport or goggle acceptance test.
- Unwrap is exact only in the declared decoded per-25-ns bound of <=63 Phase8 bins. Outside-domain trajectories, history priors and near-origin noise are not universally recoverable. The four-bin final DAC address and span75 chroma response are design limitations, not fixed by snapshots (#144).
- Scanner periodicity confidence can still confuse periodic interference, and its 50-ns mean CFO remains scene-biased and modulo-20-MHz ambiguous. This PR addresses data validity/ownership, not a new burst-confirmed scanner discriminator (#128 lineage).
- Native sample/hold does not prove elimination of packet reacquisition, background calibrations or short PHY gates (#139/#150-153). Default stays Direct Gain V5; manual/native retain ownership.
- Full RX filter ordering/ENBW, #155 upper-band 11p benefits, loaded sync/black voltage, PAL/NTSC goggle recording, and matched full-colour attenuation/range require hardware measurements. No dB/range gain is asserted.
