# PR 212 board application update

C5VRX by Twotoz and the C5VRX contributors. Explicit operator request:
flash the new application now. Frozen source: `f3e6931557a2f428a16bccd9bf63f7ab42c903c7`.

The local ESP-IDF 6.0.2 build completed without compiler warnings. Application
size 1166016 bytes, SHA256
`a717a4020b2513a9f7326bd7b4f6e5bb7a200681f85220d3e068be341af7d52c`.
All exported checksums matched before flashing. Existing partition/NVS bytes
were backed up privately; only the app at `0x10000` was written. Esptool
verified written data. The documented LP_AON forced-download field was cleared
with mask `0x60000000` at `0x600b1034`, followed by reset.

After a temporary USB disappearance the console returned: ready/live, A2,
OUTPUT 2.0x restored, transport fault/rollback counters zero. This is a short
boot/runtime observation, not a controlled attenuation or monitor test.

On A1 / 5865 MHz, zero offset, the new PBUS prefix check passed preflight.
The acquisition opened for 8 us but returned `RF_NATIVE_GAP` (result 3),
with zero landing candidates. It restored Direct Gain without transport
faults. The operator's A2 was restored afterward. Native remains default-off;
the timing of enable, first read and successive PBUS polls needs measurement
before changing the gap contract. One completed acquisition is still unproved.

This flashed application contains the native PBUS fix and previous CPU/output
changes. It does not contain the subsequent live-scan removal, DC-circle
qualification or an enabled flywheel. Its CI host step failed to locate the
cross objdump because IDF's tool environment was not exported in that step;
the local pinned build and PBUS fixture passed. The workflow fix explicitly
exports that environment and is a subsequent change.
